| 337 | 138-a | **The shorthand import goes; `mod m;` binds the namespace `m` in the module that declares it.** (1) An import names where its names come from: a module of the package by its path (`import {config.splitPath};`, `import {config};` for the namespace — 206, 309) or a package with `from` (206). An item whose first segment names no module of the package and that has no `from` — `import {splitPath};` — is `error[shorthand-import]` at the item, its fix written: `write import {config.splitPath};` when one module of the package declares the name `pub`, the candidates listed when several do, `unresolved import` when none does. `outsideShorthandReach` and the shorthand arms of `resolveImports` are deleted, so no bare name reaches a dependency's or std's modules, and 170's `ambiguous-import-use` stays only for `from "<pkg>"`. (2) `mod config;` and `pub mod config;` bind `config` as a namespace in the module that declares them — `config.splitPath(x)` with no import. The namespace walks a folder module's tree as 110's does: with `src/mod1/mod.bp` declaring `pub mod mod2;`, `mod mod1;` alone allows `mod1.mod2.splitPath(x)` — each step a `pub mod` and the leaf `pub` (a plain `mod` stays private to its declaring module's subtree: `mod1.mod2` from outside `mod1` is refused at `mod2`, `private-module`). A sibling or nested module reaches `config` only by import. In the declaring module `import {config};` is refused (`redundant-module-import`, fix: delete the item); a top-level declaration named like a declared module is `import-name-collision`. (3) No combined form (`pub mod config {splitPath};` is not syntax) and no re-export syntax (no `pub use`, no `export … from`): a folder's `mod.bp` exposes a submodule's function with a value, `mod mod2; pub val splitPath = mod2.splitPath;`, the submodule kept private so the name has one public path. (4) Every shorthand migrates in the commit that adds the refusal, by the refusal's own fix; the cell `modules/shorthand_import_beside_bundled_package` goes | 01-compiler/129 (reopened) · 01-checker rows · 03-bundled-libs/138 step 3 (the cell) · every repository (consumer commits, 188) · `docs.md` § Modules, § Imports |
